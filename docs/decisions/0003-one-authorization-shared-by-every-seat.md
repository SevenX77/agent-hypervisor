# 0003 — 一次授权，所有席位共享

状态：已实施
日期：2026-08-04

## 决策

操作者在自己的系统上对每个 provider 授权一次，之后所有席位由 ah 负责，不再出现二次登录或授权失效。为此确立两条不变量：

1. **凭据只有一份**：所有席位与宿主共享同一个凭据文件；任一席位刷新令牌，其他席位与宿主立即看到新令牌。
2. **席位必须能到达 provider**：能否联网是授权成立的前提，网络配置随席位进入沙箱。

## 背景与事实

以下为实施前在真实机器上核验的事实。

- **antigravity 的凭据是每沙箱一份私有副本**。materialize 时对 `.gemini/antigravity-cli/antigravity-oauth-token` 走复制而非共享（v1.0.0 squash 带入，无事故记录说明理由）。实测该机器上 816 个沙箱中，多个沙箱的令牌文件修改时间晚于沙箱创建时间数小时至数天——即 **agy 确实在沙箱内刷新令牌**，而刷新结果既不回到宿主，也不到达其他席位。
- **codex 的凭据是共享的**：`.codex/auth.json` 在所有抽样沙箱中均为指向宿主文件的软链接，宿主文件的修改时间晚于这些沙箱的创建时间，说明刷新经由软链接写回同一份。
- **provider 刷新是就地改写**：一次经软链接的刷新之后，宿主令牌文件的 inode 未变、内容已更新——软链接不会被替换，共享成立。
- **沙箱席位没有网络配置**：`ENV_PASSTHROUGH` 不含任何代理变量。在需要代理出网的机器上，这使席位无法到达 provider；agy 将其表现为 `You are currently not signed in`，而不是网络错误，因而极易被误诊为授权问题。操作者已在多个项目的 `[env]` 中手工粘贴同样六个代理变量作为绕过——这本身即是系统缺口的证据。

## 关键设计决定

### D1 凭据共享取代私有副本

所有 provider 的凭据统一走共享（软链接到宿主的单一文件），删除 antigravity 的复制特例。

依据：私有副本使"一次授权"在第一次刷新时即失效——刷新后的令牌只存在于某一个沙箱，宿主与其他席位持有的旧令牌在 provider 轮换 refresh token 后失效。共享则使刷新对所有席位同时生效，与 1.7.0 为 Claude 采用的共享凭据存储同构。

放弃的替代：(a) 保留副本并由 ah 事后回写——需要监视文件、处理竞态与冲突，且回写窗口内其他席位仍持旧令牌；(b) 绑定挂载凭据文件——原子替换会因挂载点繁忙而失败，把刷新变成硬错误。

privacy：共享后沙箱内不再存在第二份凭据，权限由宿主文件自身承担；物化不得改动宿主文件权限。

### D2 升级迁移：旧的私有副本被替换

材料化时若目标已是普通文件（来自复制时代的沙箱），先删除再建立共享链接。

依据：不迁移则既有席位继续留在漂移状态，"一次授权"对老沙箱不成立。宿主凭据是操作者登录的那一份，因此以宿主为准。

### D3 网络配置随席位进入沙箱

`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` 及其小写形式加入 `ENV_PASSTHROUGH`。

依据：席位到达 provider 是授权的前提条件，与凭据同属"跑起来"的必要条件；不同运行时读取大小写不同的变量，故两种都放行。把它留给用户在每个项目 `[env]` 里手工填写，等于把系统级前提降格为项目配置，且遗漏时的症状（"未登录"）指向错误的方向。

放弃的替代：仅放行大写形式——Go 与 Node 生态对大小写的处理不一致，只放一半会产生难以定位的偏差。

### D4 文本文件行尾固定为 LF

`.gitattributes` 将 `*.sh`、`*.txt`、`*.toml`、`*.md`、`*.rs`、`*.yml` 固定为 LF 检出。

依据：同一个工作树在 Windows 上是检出目标、在 WSL 里是运行环境。CRLF 检出使仓库自带的 shell 脚本在 bash 下直接失败（实测 `set: pipefail: invalid option name`），CI 闸的基线文件也因行尾差异全部失配。跨系统正常运行要求同一份文件在两侧字节一致。

## 验收证据

判定"未登录"的根因用三组对照完成，三组的 HOME、凭据文件、工作目录完全相同，只改环境：

| 环境 | 结果 |
|---|---|
| 完整宿主环境 | 已登录，正常进入提示符 |
| 按 `ENV_PASSTHROUGH` 裁剪 | `You are currently not signed in` |
| 裁剪后仅加回代理变量 | 已登录，正常进入提示符 |

修复后的端到端实测（antigravity worker，经 ah 拉起）：

- agent 状态从 `SPAWNING_INTERVENTION`（停在登录菜单）变为 `IDLE`；
- `ah ask a1` 派发真实作业并返回预期输出；
- 该沙箱内 `antigravity-oauth-token` 为指向 `/root/.gemini/...` 的软链接，私有副本数为 0。

自动化测试：`cargo test --lib` 1088 passed / 0 failed；全量 `cargo test --tests` 见 CHANGELOG 对应条目。新增用例覆盖：所有 provider 的凭据物化产出共享链接且沙箱内的刷新写回宿主；来自复制时代的旧副本被迁移为共享链接；三个联网 provider 的 `env_passthrough` 均包含全部代理变量。

## 非目标

- 不改变各 provider 自身的登录方式（仍由操作者在宿主执行一次）。
- 不引入 ah 自己的令牌刷新逻辑；刷新仍由 provider CLI 完成，ah 只保证它们写向同一份文件。
- 不处理宿主凭据本身失效（过期、被吊销）的情形，那需要操作者重新登录。
