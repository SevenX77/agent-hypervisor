# 0004 — ah 的产物是易耗品，项目资产由项目带走

状态：已批准，分片实施中
日期：2026-08-04

## 决策

ah 运行期创建的一切都是**易耗品**：有明确 owner、明确终点、有界体积。项目要长期保留的东西是**项目资产**，必须在 ah 销毁自己的产物之前交给项目，而不是靠翻 ah 的状态目录去捡。

两句判据：

1. **ah 不留**：停止一个栈、结束一个会话之后，ah 不应留下会随时间累积的东西——不留自启单元、不留无界增长的库、不留无人回收的沙箱。
2. **项目自带**：会话记录这类项目资产，在沙箱销毁前归档到项目自己的位置；ah 的状态目录不承诺可读、可留、可回溯。

## 现状与证据

单台机器（2026-08-04 实测）：

| ah 的产物 | 实测 | 终点 |
|---|---|---|
| 沙箱家目录 | 897 个 / 25 GB，最老 2026-07-09 | 有单点删除，但只覆盖正常 kill 路径 |
| 状态库 `ahd.sqlite` | 单项目 1.9 GB（events 23 万行、job_transitions 10 万行，jobs 仅 8 行） | 无保留策略、无回收 |
| 一个 `.bak` 状态目录 | 27 GB 单文件 sqlite | 无人回收 |
| systemd 单元 | 12 个 enabled 孤儿 | v1.8.3 已闭合（#24） |
| tmux socket | 81 个死 socket | 有手动脚本，非自动 |

对应仓库既有 issue：#23（库无界增长且不回收）、#27（清沙箱前不归档导致会话永久丢失）、#24（单元泄漏，已修）。

## 关键设计决定

### D1 状态库有界：分级保留 + 回收（#23）

`events` 表混着两类东西：**取证类**（状态迁移、证据、失败）和**流水类**（`output_chunk` 之类的 pane 输出）。前者是排障依据，后者只在当下有用。因此保留策略按类型分级，而不是一刀切按时间——一刀切正是 #20 抱怨的"该留的 FAILED 行被剪掉"的成因。

- 流水类事件：只保留最近一段（按条数上限），超出即删。
- 取证类事件：按时间保留，窗口远长于流水类。
- `job_transitions`：按条数上限保留最近的。
- 删除之后必须**归还空间**：新库启用 `auto_vacuum = INCREMENTAL` 并做增量回收；老库无法在不重写整个文件的前提下切换该模式，因此按空闲页比例决定是否做一次完整 `VACUUM`，并在每次维护后 `wal_checkpoint(TRUNCATE)`。删行而不回收正是 2 GB 库只装 2 MB 数据的原因。

维护在守护进程启动时跑一次，并在运行期周期性重跑；单次维护有界（限量删除），不阻塞正常请求。

放弃的替代：把 `output_chunk` 完全移出数据库（环形缓冲或独立存储）。方向正确但改动面大，且与 `ah logs`/`ah watch` 的读取路径耦合；先用保留策略把体积按住，独立存储另案。

### D2 先归档，后销毁（#27）

沙箱家目录里有 provider 的会话记录（codex 的 rollout、claude 的 project 记录、antigravity 的 conversation），这是**项目资产**：用户的真实开发会话。今天的清理直接删 home，资产随之消失，而 ah 自己恰恰有依赖这些记录的恢复机制。

规则：**任何销毁沙箱 home 的路径，必须先把该 provider 的会话记录归档到项目目录下，再删。** 归档位置属于项目而非 ah 的状态目录——项目资产跟着项目走，符合 D2 的第二句判据。归档失败时不得静默删除。

### D3 显式回收命令

操作者需要一个不必手工 `rm -rf` 的入口来回收 ah 的存量产物（终态会话的沙箱、已死栈的状态目录）。回收命令只动 ah 自己的产物，且对已归档的会话资产不负责。

## 实施分片

- **A（本决议）**：写下不变量与产物清单。
- **B（#23）**：分级保留 + 空间回收 + WAL 截断，启动与周期性执行。
- **C（#27）**：销毁沙箱前归档 provider 会话记录到项目目录，归档失败不删。
- **D**：显式回收命令，回收终态会话沙箱与死栈状态目录。

## 验收判据

1. 新建库启用增量回收；连续写入并删除大量流水事件后，库文件不单调增长。
2. 流水类事件超过上限即被回收；取证类事件在同一次维护中保留。
3. 维护有界：单次维护的删除量与耗时有上限，不阻塞 RPC。
4. 销毁沙箱前，provider 的会话记录出现在项目目录下的归档位置；归档失败时沙箱不被删除。
5. 上述行为由自动化测试覆盖，且在真实机器上以实测数据复核体积变化。

## 非目标

- 不改变 provider 自身的会话存储格式。
- 不承诺 ah 状态目录的向后兼容或可读性——它是易耗品。
- 不在本决议内把 `output_chunk` 移出数据库。
